# FormFill Guardian AI — Backend

Node.js/Express backend using Gemini to compare PDF documents and JPG/JPEG/PNG images and optional Firebase Admin/Firestore review history.

## 1. Requirements
- Node.js 20+
- Google AI Studio Gemini API key
- Optional Firebase project for authenticated review history

## 2. Run locally
```bash
npm install
cp .env.example .env
```
Put your Gemini API key in `.env`, then:
```bash
npm run dev
```
Health check: `http://localhost:8080/api/health`

## 3. Review endpoint
`POST http://localhost:8080/api/review`

Use `multipart/form-data`:
- `formPdf`: filled form as PDF, JPG/JPEG, or PNG
- `instructionsPdf`: official instructions as PDF, JPG/JPEG, or PNG

You can mix file types (for example, upload a JPG form and a PDF instruction guide). Each file must be 15 MB or smaller. The field names remain `formPdf` and `instructionsPdf` so existing frontend code that uses these names can keep sending files.
- `language`: `English` or `Telugu`

Example with curl:
```bash
curl -X POST http://localhost:8080/api/review \
  -F "formPdf=@./filled-form.jpg" \
  -F "instructionsPdf=@./official-instructions.jpg" \
  -F "language=Telugu"
```

Response includes `items`, `counts`, `reviewId`, and for each item the status, explanation, suggested action, source quote, and page number. Page citations generated by an LLM must be checked against the actual PDF before relying on them.

## 4. Connect the frontend
Use `fetch` and `FormData`:
```js
const data = new FormData();
data.append("formPdf", formFile);
data.append("instructionsPdf", instructionsFile);
data.append("language", language);

const response = await fetch("http://localhost:8080/api/review", {
  method: "POST",
  body: data
});
const result = await response.json();
if (!response.ok) throw new Error(result.error || "Review failed");
```
Do not manually set the `Content-Type` header when using `FormData`; the browser adds the multipart boundary.

Set `FRONTEND_ORIGIN` to the origin of your React/Vite app (for example `http://localhost:5173`).

## 5. Optional Firebase history
1. Create a Firebase project and enable Authentication (Google provider) and Firestore.
2. Configure the backend with Firebase Admin credentials. For local development, you can set `FIREBASE_SERVICE_ACCOUNT_JSON` to the service account JSON as a single-line JSON string. Never commit it.
3. For Cloud Run, prefer Application Default Credentials: assign a service account with appropriate Firestore permissions to the service and set `FIREBASE_PROJECT_ID`.
4. The frontend should sign in with Firebase, call `user.getIdToken()`, and send `Authorization: Bearer <token>` to `/api/review` and `/api/history`.
5. Firestore records are stored under `users/{uid}/reviews/{reviewId}`. Uploaded documents/images are not stored in history by this backend.

If history is not configured, `/api/review` still works but does not persist results. `/api/history` returns a configuration error.

## 6. Deploy
Deploy to Cloud Run from this folder after configuring environment variables/secrets. Store `GEMINI_API_KEY` in Secret Manager for production. Set a restrictive `FRONTEND_ORIGIN`; do not use `*` in production.

## Security and limitations
- PDF/JPG/JPEG/PNG files are held in memory during processing and limited to 15 MB each. File signatures are checked server-side.
- This demo does not save uploaded PDFs to Cloud Storage.
- A supplied Firebase token is verified only when Firebase Admin is configured. Protect production endpoints with authentication, quotas, and monitoring.
- Gemini may make mistakes, including incorrect page citations. The output is advisory, not an official eligibility or acceptance decision.
- Consider adding PDF malware scanning, stricter rate limits, request authentication for all endpoints, deletion/retention controls, and human verification before production.
